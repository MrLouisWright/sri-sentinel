sri-sentinel

Subresource Integrity for your built site: generate, write and check it in CI.

Scans the HTML in your build for scripts, stylesheets, modulepreload / preload links and import map entries, hashes the local files (and CDN files with --remote), then either writes integrity and crossorigin attributes or checks the existing ones are correct. Vite, webpack, Rollup, esbuild and Astro integrations. Zero runtime dependencies.

$ npm i -D sri-sentinel
Read the docs View on npm Source on GitHub

01 The problem

If a CDN or asset host is compromised, anything you load from it runs with full access to your page. Subresource Integrity stops that, but hand-maintained hashes go stale on every rebuild and a single missing crossorigin attribute makes the browser block the file.

sri-sentinel writes the hashes for you after each build and fails CI when one is missing, wrong or stale.

02 Features

01

Write or check

--write adds integrity (and crossorigin) attributes; --check fails on missing, wrong or stale values.

02

CDN resources

--remote fetches and hashes cross-origin files too.

03

Import maps

Fills the integrity object inside <script type="importmap">.

04

Lazy chunks

The webpack plugin patches the webpack 5 runtime so import() chunks get integrity too.

05

Browser-accurate checks

Only the strongest algorithm counts, any hash of it may match; base64url and ?options accepted.

06

Build integrations

Vite, webpack, Rollup, esbuild and Astro.

07

Allowlists that expire

Per-rule or per-URL exemptions with a reason and an expiry date.

08

Manifests & reports

JSON manifest of resource → integrity; text, JSON, SARIF and Markdown reports.

03 Usage

# Add integrity attributes

$ npx sri-sentinel dist --write

# Fail CI on bad integrity

$ npx sri-sentinel dist --check

# Include CDN resources

$ npx sri-sentinel dist --write --remote

# Write a manifest

$ npx sri-sentinel dist --manifest sri.json

04 CI / GitHub Action

name: SRI
on: [push, pull_request]
jobs:
  sri:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: npm ci && npm run build
      - uses: MrLouisWright/sri-sentinel@v1
        with:
          paths: dist
          mode: check          # or write
          remote: 'true'
          fail-on: high
          sarif: sri.sarif

05 Options & flags

FlagDescription
--checkReport missing, wrong or stale integrity (default)
--writeWrite integrity (and crossorigin) attributes into the HTML
-a, --algorithm <alg>sha256 | sha384 | sha512 (default: sha384)
--remoteFetch and hash remote (CDN) resources
--base <path>Public base path, e.g. /app/ (default: /)
--origin <url>Site origin; absolute URLs on it are treated as local files
--crossorigin <v>anonymous | use-credentials (default: anonymous)
--manifest <file>Write a JSON manifest of resource -> integrity
--config <file>Config file (default: .sri-sentinel.json or package.json "sri-sentinel")
--fail-on <sev>critical | high | medium | low | info | none (default: high)
--format <fmt>text | json | sarif | markdown (default: text)
--json/--sarif/--markdown <file>Also write that report to a file
--timeout <ms>Remote fetch timeout (default: 10000)
-q, --quietOnly print the summary

Full reference, config file format and API in the README.
